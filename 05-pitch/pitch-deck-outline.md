3. **Problem** — users authorize scams themselves; PIN/OTP + after-the-fact detection miss it (+ cited stat)
4. **Insight** — context beats credentials: *unusual for this user, at this moment*
5. **Solution** — detect → score → explain → ask → step-up (one diagram)
6. **Live demo** (or embedded video) — legit vs scam vs API
7. **How it works** — signals, explainable score, (not a black box) + metrics on synthetic data
8. **Not a wallet → infrastructure** — Fraud Prevention API; who integrates (MoMo operators, banks, fintechs, merchants)
9. **Impact & market/roadmap** — pilot path, real-data partnership, ML, USSD/SMS, local languages, shared scam intelligence
10. **Ask & close** — what we want (pilot/mentorship/sandbox access) · repeat the pitch line
