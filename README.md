# MoMo Guardian — Documentation Hub

Single source of truth for the project. Code repos link back here.

| Folder | What's inside |
|---|---|
| `00-overview/` | Project brief, problem, solution, users, differentiation |
| `01-product/` | MVP scope, user flows, scam scenarios, risk signals, scoring spec, step-up rules |
| `02-architecture/` | System architecture, API contract, data model, tech stack |
| `03-execution/` | Execution plan, **checklist**, team roles, GitHub setup guide, workflow, DoD, risk register |
| `04-brand/` | **Logo plan**, brand guidelines, asset folders |
| `05-pitch/` | Pitch outline, demo script, judging alignment, Q&A prep |
| `06-research/` | Research notes and sources log |
| `adr/` | Architecture Decision Records |

## Reading order for a new teammate
1. `00-overview/project-brief.md`
2. `01-product/mvp-scope.md`
3. `02-architecture/system-architecture.md`
4. `03-execution/execution-checklist.md`

## Doc rules
- Docs are Markdown. One topic per file. Update docs in the same PR as the change.
- Decisions that affect more than one repo get an ADR in `adr/`.
- Anything marked **[ASSUMPTION]** must be confirmed against the official hackathon brief.
